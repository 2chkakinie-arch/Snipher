# v8 — 再帰的思考モデル（Recurrent / Draft-Verification + MoE）

v8 の目標は「本気で賢い」ことです。賢さの源を *モデル自身のパラメータ* に置き、
テンプレートもプログラムによる組み立て文も一切使わずに、考える → 書く → 校正する、を
モデルの確率サンプリングだけで回します。

## 1. アーキテクチャ（ユーザー設計図の ①②③④ をそのまま）

```
x = Embedding(chars)
for block in blocks:                       # attn / moe を交互に積む
    if attn:   # ② RoPE + ① GQA
        h = RMSNorm(x)                     # ④
        q = RoPE(h @ W_q)                  # 全ヘッド
        k, v = RoPE(h @ W_kv)              # n_kv_heads 個だけ（GQA）
        k, v = repeat_interleave(k, v, H // KVH)
        x = x + CausalSoftmax(q kᵗ/√d) v @ W_o
    if moe:    # ③ SwiGLU × Mixture-of-Experts
        h = RMSNorm(x)
        g = softmax(h @ W_router)          # 学習時は dense、推論時は Top-K
        for e in experts:
            x = x + g[..., e] * SwiGLU_e(h)
logits = RMSNorm(x) @ Embeddingᵀ           # 重み共有
```

* **RoPE**（回転位置埋め込み）— 相対距離を回転行列で埋め込み、長文でも位置が崩れない。
* **RMSNorm** — 平均減算なし・二乗平均平方根のみの正規化（学習が安定）。
* **GQA**（Grouped-Query Attention）— KV ヘッドを 1/group に集約し、
  長文生成の KV キャッシュを同率で削減（`n_heads/n_kv_heads`）。
* **MoE**（Mixture-of-Experts）+ **SwiGLU** — ルータがトークンごとに専門家を
  Top-K 選ぶ。学習時は dense soft MoE（全経路に勾配）、推論時は Top-K で計算量 1/K。

実装は `snipher/neural/moe.py`（`MoENet`）。numpy のみで forward / backward が
あり、float64 の中心差分で勾配検証済み（`tests/test_moe.py`）。既存の内蔵コア
（`MicroNet`）は無変更で、重みは `store.py` の `kind: moe` 形式で共存します。

## 2. 3 段のモジュール化（モデルA/B/C）

`snipher/mind/recurrent.py`（`RecurrentMind`）が 3 コアを束ねます。

| 役割 | 仕事 | 重み |
|---|---|---|
| モデルA（ルーティング・思考） | 入力から `<think>…</think>` の思考（結論の箇条書き）を生成 | `v8_a.npz` |
| モデルB（知識・文章化） | 箇条書きを文脈に、日本語の長文を *テンプレート無しで* 生成 | `v8.npz` |
| モデルC（校正・フォーマット） | 反復・文体混在・壊れた文末・定型表現を検査し、却下なら再下書き | `v8_c.npz` |

思考は「確率の波」（`ProbabilityWave`）として下流へ渡ります：モデルA の箇条書きが
モデルB の文脈に挿入され、モデルC の却下理由が禁止トークン・低温化・反復禁止強度の
波となって次の下書きに乗ります。A/B/C は別々の重みでも、1 つの重みを役割プロンプトで
使い分ける単一モデルでも動き、無い役割は他で埋めます（graceful 縮退）。

## 3. 反復の物理的な封印

同じ単語・定型文の周回は *サンプリングの logit 段階* で封じます（後処理ではない）。

* `no_repeat_ngram` … 直近ウィンドウで既出の n-gram を完成させるトークンの logit を
  `-inf` にして 2 度と選ばせない（`snipher/neural/sample.py::no_repeat_ban`）。
* プレゼンス/頻度ペナルティ … 既出トークンの再登場を減衰。
* 校正モデルC … 生成後も 4-gram の周回と定型表現（「〜の知識で答えます」等）を検査し、
  見つかれば却下して再下書き。

テンプレートは学習データにも生成経路にも存在しません。`generate_novel` は
`<user>…<asst>` の文頭だけを置き、あとはモデルが 1 文字ずつ確率サンプリングで書きます
（EOS も禁止して書き続けさせ、反復は n-gram 封印が止めます）。

## 4. 学習パイプライン（3 フェーズ）

`tools/train_v8.py`（numpy のみ、GPU 不要）:

1. **継続事前学習** — コーパスで次の 1 文字を予測（perplexity 低下）。
2. **SFT + CoT** — `<think>…</think>` を応答文頭に仕込んだ教師で「考えてから答える癖」を焼き付け。
3. **DPO / GRPO-lite** — 「考えて正しく答えた回答」を好み、ルール報酬
   （思考あり/正解/反復なし）で強化学習（`snipher/neural/align.py`）。

```bash
python tools/train_v8.py --phase all --profile v8b  --out snipher/data/neural/v8.npz
python tools/train_v8.py --phase all --profile v8ac --out snipher/data/neural/v8_a.npz
python tools/train_v8.py --phase all --profile v8ac --out snipher/data/neural/v8_c.npz
python tools/bench_v8.py        # 実測ベンチマーク
```

プロファイル: `v8b`（モデルB: d=96 L=3 GQA 6/2 MoE 4x top2, 約 0.41M params）、
`v8ac`（A/C: d=64 L=2 GQA 4/2, 約 0.18M params）、`tiny`（CI 用）。パラメータ上限は
ありません（`d_model`/`n_layers`/`n_experts` は任意、メモリと時間が許す限り拡張可能）。

## 5. API と Cloudflare Pages

* Python 側: `/api/chat` の `mode: "v8"`（SSE: `start → thought → draft → verify →
  delta → done`）、`/api/v8/status`、`/api/v8/novel`。
* Pages 側: `public/engine.mjs` に同契約の軽量実装（`thinkV8` / `draftV8` /
  `verifyV8` / `recurrentRespond` / `generateNovel`）。Python を載せられない Pages でも
  再帰的思考と反復封印が動きます（`tests/js/engine.test.mjs` で実測）。
