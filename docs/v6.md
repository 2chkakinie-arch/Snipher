# Snipher v6 — リアルタイム・ウェーブ・アーキテクチャ

v5 までの Snipher は「高速コア + 内蔵ニューラルコア + 知識ベース」の 1 本道でした。
v6 はそこに **確率の波** を足します。生成を止めずに、3 つの並列プロセスが
出力モデルのロジット（確率分布）へリアルタイムで干渉し、その関わりはすべて
SSE イベントとしてチャットラインへ流れます。

```
                     ┌─────────────────────────────────────────────┐
 ユーザー発話 ────────▶│  stream_reply（core.py::_WaveTracker）        │
                     │                                             │
   /api/steer ──────▶│  SteeringBus（確率の波の合流点）               │──▶ delta…delta…done
 （生成中でも可）      │   ▲            ▲             ▲              │
                     │   │            │             │              │
                     │  ユーザー波   Web証拠波      熟考結論波        │
                     │  (prompt)   (evidence)   (deliberation)     │
                     └─────────────────────────────────────────────┘
                          並列で走る（生成は止めない）:
                          - ground/realtime.py  検索∥生成
                          - mind/deliberate.py  熟考∥生成
```

## 1. リアルタイム・ステアリング（ロジット・モジュレーション）

`snipher/lfm/steering.py`

- `SteeringBus.steer(text)` は介入プロンプトを即座にトークン化し、
  token_id → logit bias の **確率の波** に変換して積む。
- 波は `decay ** age` で減衰し、`ttl` トークン / 30 秒で消える。
- 生成ループは 1 トークンごとに `apply_to_logits()` を呼び、
  波が実際に乗ると **適用イベント** が記録される（`take_events()` で SSE 化）。

バックエンド別の干渉点:

| バックエンド | 干渉の仕方 |
|---|---|
| 内蔵蒸留コア（numpy） | `neural/core.py::_sample` が `apply_to_logits()`（文字単位で直接） |
| GGUF（llama.cpp） | `logits_processor` フック。文字単位の bias を BPE 語彙へ再エンコードして加算 |
| リモート（HTTP） | 生成中に届いた波をリモートの `/api/steer` へ転送する裏スレッド |

UI は生成中も入力を止めない。送ると `/api/steer` へ POST され、
応答は途切れず、次のトークンから確率分布が曲がる。

## 2. リアルタイム Web 検索（無限知識の再現）

`snipher/ground/realtime.py` + `core.py::_WaveTracker`

- 入力受信と同時に `search_async()`（挨拶・相槌は `should_search_realtime()` が除外）。
- 証拠文が届くと `bus.inject_evidence()` が確率波として注入 —
  生成中なら次のトークンから、次のターンなら冒頭から効く。
- 検索の開始/結果は `web` イベント（`state: start/done`）として流れ、
  出典は `done.stats.sources` に合流して UI のソースチップになる。
- `done` の直前だけ `SNIPHER_WAVE_WAIT_MS`（既定 650ms）を上限に未着の波を待つ。
  挨拶は波を起動しないので **0 待ち**（高速経路は無傷）。

## 3. 並列熟考モデル

`snipher/mind/deliberate.py`

- `think_async()` が裏スレッドで 問いの分解 → 知識照合 → 因果設計 → 自己検証 を実行。
- 結論は `bus.steer(kind="deliberation")` で確率波として出力モデルに干渉。
- 思考過程（steps / conclusion / confidence）は `thought` イベントとして流れ、
  UI ではクリックで展開できる。
- 出力を止めることはない — 熟考が間に合わなくても応答は出る（ベストエフォート）。

## 4. Gemma 2 準拠の確率的生成

`snipher/lfm/gemma.py`

- 文字単位の logits → softmax → sampling（temperature / top_k / **top_p** / 反復罰）。
- フルウェイト（LFM2.5 GGUF/torch/リモート）が無い環境では、同梱の蒸留重みを
  Gemma のサンプリング設定で回す（DL 不要、Cloudflare Pages でも動く）。
- `mode=lfm/neural` の強制時はこの経路が本文を生成する（`_gemma_reply`）。
- 長文読解: `digest_long()` が文単位の LM スコアで抽出型ダイジェストを作り、
  文脈窓（56 文字）に載せてから確率的に続きを生成する。

## 5. SSE イベント契約（Agent 化）

```
assist  経路判定（route/plan/confidence）          ← start より前
start   エンジン名
thought 並列熟考（start → done: steps/conclusion） ← 生成中に差し込み
web     Web検索（start → done: sentences/sources） ← 生成中に差し込み
steer   ステアリング波の適用（text/tokens_biased）  ← 生成中に差し込み
delta   本文
done    stats.waves = {deliberate, web_search, web_hits, steer_waves, thought}
```

契約（`tests/test_v6_waves.py` が機械判定）:
- `start` より前に波イベントを出さない、`done` は必ず最後。
- 挨拶・相槌では `web` イベントが 1 つも出ない（検索が走らない）。
- それ以外では必ず `web` start/done が出る（ヒット 0 でも「該当なし」を出す）。

## 6. Cloudflare Pages 版（Python なしでも波が動く）

`functions/api/[[path]].js` + `functions/_engine/engine.mjs`

- `respondStream()` が start → thought → web → delta… → done を流す。
- `/api/steer` は isolate 内キューへ積み、生成中の応答がチャンク間で拾って
  **残りの文をその場で組み直す**（出力は止めない）。
- Web 検索は Workers からの fetch（DuckDuckGo HTML、`SNIPHER_SERP_URL` で差し替え、
  `SNIPHER_WEB=off` で無効化）。失敗しても生成は続く。
- `SNIPHER_API_ORIGIN` があれば本体 API へプロキシ（全機能）。
