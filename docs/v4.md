# v4 — 辞書引きボットをやめて、その場で考えるアシスタントに

v3 までの Snipher は「国語辞典 + 百科事典をそのまま出す」Bot でした。v4 の主眼は
**出すものを減らす**ことではなく、**手元にある材料を材料として使う**ことです。
検索・索引・KB は *証拠庫* であって、応答そのものではありません。

## 1) 応答の作り方（1 ターンの流れ）

```
入力
 └─ mind.parse.build_frame      語気 / 問いの型 / 実体 / 制約（字数・口調・形）/ 話題
     ├─ instruction.*           「JSON のみ」「3 つ」「200 文字」「だよ・だね」を契約として実行 → 検証
     ├─ mind.think              会話・相談・雑談は chat 層（発話行為と内容語から組み立てる）
     │    └─ mind.chat          KB の本文・理由・手順を *話題が重なるときだけ* 引く
     ├─ ground.evidence         証拠束（KB → 辞書 → web）をscore順に
     ├─ ground.web              検索 → html-fetch → 発話と重なる文だけを証拠に
     └─ mind.voice.render       接続語でつないで 1 文ずつ組む（定型棚は無い）
```

## 2) 禁止した応答（v3 で出ていたもの）

| 出してはいけないもの | 抑え込み場所 |
| --- | --- |
| 表記・読み・拍数・品詞（`「X」は 5 拍の語です`） | `mind.parse.wants_word_info` の門番（語そのものを尋ねる発話だけ通す）＋ `mind.chat._usable` |
| `索引に N 語あります` / `語彙バンク 15 万語の見出しに無い` | `mind.think._topic_moves` を `ask_lex` 限定、`instruction/answer.fallback_claims` から削除 |
| `参考までに、「X」は単独の項目を持っていないので…` | 開示は *和語の複合語を借りたときだけ*（`ground/evidence._compound_claims`） |
| 「この設定ではウェブ検索に出られないので…」等の**できません**系 | `instruction/answer` の拒否棚を撤去 → 近い本文を引き、*推論の 1 文*を必ず添える |
| 相手の発話をそのまま複写する相槌 | `mind.chat` は動詞・名詞に分解して使い、全文複写を `voice` の重複検査で弾く |

## 3) SFT（指示追従）を *自分の素材* で作った

`snipher/neural/corpus.py:CorpusBuilder.sft_docs()` が、KB の本文を材料に
質問→答え・口調指定・文字数指定・箇条書きの個数・JSON 抽出・読めない語の聞き返し を
対にします（約 3,600 例）。`tools/distill_neural.py --profile v4` がこれを
authored（人が書いた対話）と kb と並べて内蔵コア（3.48M params, d=320/L=8）に学習させ、
`tools/build_lm.py` は流暢さの審判（5-gram）にも同じ型を読ませます。
JSON や箇条書きを「ありえない日本語」として減点しなくなるのが実務上の効きどころです。

## 4) インターネットは *本体の中* で使う

`snipher/ground/web.py` が Snipher 自身の裏取り窓（既定 ON、`SNIPHER_WEB=off` で切れる）。

- タイムアウト 4.5 秒（v3 の 1.5 秒は検索と本文取得を両方切り捨てていました）
- 成否でキャッシュ TTL を変える（成功 15 分 / 失敗 25 秒）
- 3 回連続でネットワークエラーなら 30 秒休む（通らない回線で毎回待たない）
- SERP のタイトル・広告は証拠にしない。記事 *本文* の文だけを採用
- ページ自体が問いの語を踏んでいるなら、本文の続きの文も証拠に数える
  （語を繰り返さない 2 文目を落としていた）

テストは `tests/web_fixtures.py`（Bing と同じ class 構造のローカル mini web）に対して
実測します。`tests/test_web_v4.py` に「未知語 → 検索 → 回答」「冷却」「既定値」を入れました。

## 5) Cloudflare Pages

Pages には Python を載せられないので、同じ設計を JS に移植した
`snipher/web/engine.mjs` を本体に同梱します（`tools/build_public.py` が `public/` と
`functions/` を生成、`node tools/preview_pages.mjs` で Pages と同じ挙動をローカル確認）。
`SNIPHER_API_ORIGIN` を設定すれば Pages Function が本体 API に素通しします。詳細は `docs/deploy.md`。

## 6) 測り方

`tools/bench_v4.py` は *期待する振る舞い* で採点します（語彙数などの自己申告は数えない）。

```
python tools/bench_v4.py --json /tmp/bench_v4.json
# [PASS] instruction  json-extract-only        … JSON 之外の文字が無い・キー順・値の接地
# [PASS] knowledge    kb-wasm-merit             … 速度の話ができている
# [PASS] conversation daily-plan-reaction       … 複写でなく、辞書引きでもなく、前に進む
```

回帰の守りは `tests/test_v3_contract.py`（辞書引き禁止・複写禁止・同じ相槌を返さない）と
`tests/test_cloudflare_pages.py`、`tests/test_web_v4.py` に置いてあります。
